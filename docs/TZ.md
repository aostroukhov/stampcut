# Техническое задание: StampCut

Быстрый однооконный видеоредактор под Windows 11 для редакции Telegram-каналов.

| | |
|---|---|
| Версия документа | 0.2 (дополнено по итогам обсуждения; Этап 1 в реализации) |
| Дата | 2026-11-03 |
| Заказчик | Редакция Telegram-каналов |
| Прототип по духу | [Machete](https://www.machetesoft.com/about-machete.html) — маленький нативный редактор: открыл, обрезал, сохранил |

## 1. Цель и контекст

Редакция ежедневно получает короткие ролики (до 5 минут), снятые на разные телефоны:
iPhone (HEVC, HDR, 4K60, `.MOV`), Android (разные кодеки, переменная частота кадров,
повороты в метаданных), пересланные через мессенджеры (уже пережатые). Перед публикацией
каждый ролик нужно:

1. обрезать (убрать начало и конец);
2. наложить брендинг редакции — PNG с прозрачностью (логотип, плашка);
3. сохранить в MP4, который Telegram, VK, YouTube и Instagram проигрывают без перекодирования и артефактов.

Сейчас это делается в тяжёлых редакторах или вовсе не делается. Нужен инструмент, в котором
вся операция занимает меньше минуты работы человека, а приложение запускается мгновенно
и не требует обучения.

**Что НЕ является целью:** полноценный монтаж (дорожки, переходы, титры, цветокоррекция,
музыка). Если такая задача возникает — она решается в другом инструменте.

## 2. Термины

| Термин | Значение |
|---|---|
| Оверлей | PNG-изображение с альфа-каналом, накладываемое поверх видео |
| Якорь | Одна из 9 точек кадра (углы, середины сторон, центр), к которой привязан оверлей |
| Пресет экспорта | Сохранённый набор параметров выходного файла (кодек, размер, частота кадров, звук) |
| Пресет оверлея | Сохранённые файл + положение + размер + прозрачность + интервал показа |
| Lossless-обрезка | Обрезка копированием потоков без перекодирования (как в Machete) |
| Нормализация | Приведение видео с разных телефонов к единому виду: H.264, 8 бит, SDR, не выше 30 к/с, постоянная частота кадров, правильная ориентация |
| Прокси | Лёгкая H.264-копия исходника, которую приложение создаёт для просмотра, если исходник не играет средствами Windows |

## 3. Пользователи и сценарии

Пользователь — редактор или SMM-менеджер без навыков видеомонтажа, ноутбук с Windows 11
среднего уровня (без дискретной видеокарты), часто в спешке.

### Сценарий А. Основной: один ролик, обрезка, логотип, экспорт

1. Перетаскивает файл с телефона (или из Telegram Desktop) в окно приложения.
2. Сразу видит первый кадр и информацию о файле (длительность, разрешение, кодек, размер).
3. Прокруткой по ленте находит начало и конец, ставит точки входа/выхода клавишами `I` / `O`.
4. Выбирает пресет оверлея из списка (например, «Логотип справа внизу») — оверлей появляется на превью.
5. При необходимости мышью двигает оверлей, меняет размер за угол, прозрачность ползунком.
6. Нажимает «Экспорт» — файл сохраняется рядом с исходником с суффиксом `_tg.mp4`, по умолчанию с пресетом «Telegram 1080p».
7. Нажимает «Открыть папку» или перетаскивает готовый файл из окна прямо в Telegram.

Целевое время работы человека: **до 60 секунд**, не считая кодирования.

### Сценарий Б. Только обрезка без потерь

Ролик уже в хорошем формате, оверлей не нужен. Пользователь выбирает пресет «Только обрезка»,
экспорт занимает секунды, качество не меняется.

### Сценарий В. Пакет: десять роликов, один оверлей, один пресет

Пользователь перетаскивает несколько файлов, выбирает оверлей и пресет, нажимает
«Экспортировать все». Приложение обрабатывает очередь, показывает прогресс по каждому файлу.
Обрезка в пакетном режиме не нужна (или задаётся по одному файлу перед запуском очереди).

### Сценарий Г. Единые настройки на всю редакцию

Главный редактор один раз настраивает оверлеи и пресеты и кладёт их в общую папку
(сетевой диск, OneDrive, Яндекс Диск). Все сотрудники указывают эту папку в настройках и
видят одинаковый список оверлеев и пресетов.

## 4. Границы проекта

### В объёме (Этап 1, MVP)

- Открытие файлов (диалог, drag-and-drop, аргумент командной строки, «Открыть с помощью»), немедленное воспроизведение — приложение работает и как плеер.
- Обрезка по точкам входа/выхода; **склейка** нескольких роликов по порядку, у каждого своя обрезка.
- До 3 **оверлеев** PNG: файл, якорь, отступы, размер, прозрачность, интервал показа, плавное появление.
- **Кроп** каждого ролика с фиксированными пропорциями (9:16, 1:1, 16:9, 4:5, свободно).
- **Ретушь**: области размытия или мозаики (лица, номера, недопустимый контент) с интервалом показа.
- **Запикивание** фрагментов звука (тон 1 кГц или тишина).
- Пресеты оверлеев и экспорта (встроенные + пользовательские), общая библиотека редакции (сетевая папка).
- Экспорт MP4 с полной нормализацией под телефонные исходники и **автоматическим подбором параметров** (размер, частота кадров, качество, уровень H.264).
- **GPU**: аппаратное декодирование и кодирование (NVENC / Intel QSV / AMD AMF) с проверкой и откатом на CPU.
- Lossless-обрезка и lossless-склейка совместимых файлов.
- Недавние папки и файлы, автоматические имена, экспорт без диалогов.
- Горячие клавиши, установщик с ассоциацией файлов, portable-версия.

### В объёме (Этап 2)

- Пакетная обработка очереди файлов одним пресетом.
- Лента миниатюр и форма волны на таймлайне.
- Движущиеся области ретуши (две ключевые точки), автоматический поиск лиц.
- Нормализация громкости, единый экземпляр приложения (второй файл открывается в том же окне).
- Полностью GPU-конвейер фильтров (тонмэппинг HDR на видеокарте).

### Вне объёма (не делаем без отдельного решения)

- Текстовые титры, субтитры, музыка, переходы, эффекты, цветокоррекция.
- Любые облачные функции, аккаунты, публикация напрямую в соцсети.
- macOS, Linux, мобильные версии.

## 8. Модель данных

### 8.1. Пресет оверлея (`presets/overlay/*.json`)

```json
{
  "id": "logo-bottom-right",
  "name": "Логотип справа внизу",
  "file": "logo-white.png",
  "anchor": "bottom-right",
  "offset": { "x": 3, "y": 3, "unit": "percent" },
  "size": { "width": 25, "unit": "percentOfVideoWidth" },
  "opacity": 0.8,
  "timeRange": null,
  "fadeInSec": 0,
  "fadeOutSec": 0
}
```

| Поле | Описание |
|---|---|
| `file` | Имя файла относительно библиотеки оверлеев или абсолютный путь |
| `anchor` | `top-left`, `top-center`, `top-right`, `middle-left`, `center`, `middle-right`, `bottom-left`, `bottom-center`, `bottom-right` |
| `offset` | Отступ от якоря внутрь кадра; `unit`: `percent` (от ширины/высоты кадра) или `px` (от выходного кадра) |
| `size.width` | Ширина оверлея; `unit`: `percentOfVideoWidth` или `px`. Высота — по пропорциям PNG |
| `opacity` | 0..1, умножается на альфа-канал PNG |
| `timeRange` | `null` — весь фрагмент; иначе `{ "fromSec": 0, "toSec": 5 }` относительно начала обрезанного фрагмента |

### 8.2. Пресет экспорта (`presets/export/*.json`)

См. примеры в `presets/export/`. Ключевые поля: `video.codec`, `video.maxLongSide` либо
`video.width`+`video.height`, `video.fit` (`keep`, `pad-black`, `pad-blur`, `crop`),
`video.maxFps`, `video.crf`, `video.preset`, `video.hdrToSdr`, `video.hardwareEncoder`
(`auto`, `none`, `nvenc`, `qsv`, `amf`), `audio.*`, `fastStart`, `outputSuffix`,
`streamCopy` (lossless-режим).

### 8.3. Проект

Приложение не имеет «проектов» как сущности. Последние настройки (пресет оверлея,
пресет экспорта, папка экспорта) запоминаются в `settings.json`. Точки входа/выхода
к файлу не сохраняются (Этап 1); в Этапе 2 — хранить в `%LOCALAPPDATA%` по хэшу файла,
чтобы повторное открытие восстанавливало обрезку.

## 9. Технические решения

### 9.1. Почему не «как Machete»

Machete занимает несколько мегабайт, потому что содержит собственные парсеры нескольких
контейнеров и **ничего не кодирует**: он режет и склеивает готовые потоки. Любой
оверлей требует перекодирования видео, а значит — декодера для всех телефонных форматов
и H.264-кодера. Варианта два:

| Вариант | Размер | Плюсы | Минусы |
|---|---|---|---|
| Windows Media Foundation (`Windows.Media.Editing`: `MediaComposition`, `MediaOverlay`) | +0 МБ | Встроено в Windows, аппаратное кодирование, оверлеи с позицией и прозрачностью «из коробки» | Декодирование HEVC зависит от платного/OEM расширения из Store; нет тонмэппинга HDR; VP9/AV1 — аналогично через расширения; мало контроля над кодированием |
| FFmpeg (отдельный `ffmpeg.exe`) | +30…90 МБ | Открывает всё, что снимают телефоны; HDR→SDR; предсказуемый результат; аппаратные кодеры через NVENC/QSV/AMF | Размер; внешний процесс |

**Решение: FFmpeg.** Требование «видео с разных телефонов» важнее размера дистрибутива.
Собственный код приложения при этом остаётся маленьким, как у Machete.

### 9.2. Стек

| Слой | Выбор | Обоснование |
|---|---|---|
| Язык / UI | **C# (.NET 8), WPF** | Нативное окно, старт < 1 с, один `.exe`, зрелые средства для видео-превью и drag-and-drop; команда с опытом C#/.NET найдётся легко. WinUI 3 — допустимая альтернатива, если команда уже с ним работает |
| Превью | `MediaElement` (Media Foundation) для H.264-исходников; для остального — прокси через ffmpeg (FR-1.4). Оверлей — обычный WPF `Image` поверх видео, координаты пересчитываются из модели | Нет «airspace»-проблем, оверлей на превью — тот же расчёт, что в экспорте |
| Обработка | `ffmpeg.exe` / `ffprobe.exe` как внешние процессы; обёртка — `FFMpegCore` (MIT) или собственный тонкий слой с разбором `-progress` | Прозрачная отладка: команда копируется и запускается руками |
| Сборка FFmpeg | Статическая сборка под Windows x64 (gyan.dev «essentials» или собственная урезанная: демуксеры mp4/mov/mkv/webm/avi, декодеры h264/hevc/vp9/av1/aac/opus/mp3, фильтры scale/overlay/zscale/tonemap/fps/loudnorm, кодеры libx264/aac/h264_nvenc/h264_qsv/h264_amf) | Урезанная сборка — 30–40 МБ вместо 90 |
| Установщик | Inno Setup (+ portable zip) | Простой, без Store |
| Тесты | xUnit для модели/генератора команд; набор эталонных исходников с разных телефонов для интеграционных прогонов | Генератор команд ffmpeg — ядро, он должен быть покрыт тестами |

Альтернатива для JS-команды: **Tauri 2 (Rust + WebView2)** с тем же FFmpeg. Бинарник
маленький, WebView2 уже есть в Windows 11, интерфейс на TypeScript. Минус — бэкенд на
Rust, пусть и небольшой. Electron не рассматривается: 150+ МБ и медленный старт
противоречат идее «маленький и быстрый».

### 9.3. Архитектура

```
StampCut.App (WPF)          — окно, превью, таймлайн, панели, горячие клавиши
StampCut.Core               — модель (Clip, Overlay, ExportPreset), генератор команд ffmpeg,
                              разбор ffprobe, расчёт геометрии оверлея, очередь экспорта
StampCut.Core.Tests         — тесты генератора команд и геометрии
tools/ffmpeg/               — ffmpeg.exe, ffprobe.exe, лицензии
```

Принцип: **одна функция «модель → командная строка ffmpeg»**, чистая и тестируемая.
Превью и экспорт используют одну и ту же геометрию оверлея (якорь, отступы, размер в %
от ширины кадра), поэтому WYSIWYG обеспечивается расчётом, а не подгонкой.

### 9.4. Конвейер экспорта

Проверенные команды — в [ffmpeg-pipeline.md](ffmpeg-pipeline.md). Схема:

1. `ffprobe` → размеры, поворот, fps, `color_transfer`, кодеки.
2. Расчёт выходного размера кадра (`maxLongSide` или фиксированный размер + `fit`).
3. Видеофильтры по порядку: (HDR) тонмэппинг → масштаб → поля/кадрирование → `fps` →
   `format=yuv420p` → `overlay` (для каждого оверлея: `format=rgba` → `scale` →
   `colorchannelmixer=aa=<opacity>` → `overlay=x:y:enable='between(t,from,to)'`).
4. Кодер: аппаратный, если доступен и разрешён, иначе `libx264 -preset veryfast -crf 21`.
5. Звук: `aac 128k 48 kHz`; опционально `loudnorm`.
6. `-movflags +faststart`, временное имя файла, переименование по успешному завершению.
7. Lossless-режим: `-ss/-to … -c copy -movflags +faststart`, без фильтров.

### 9.5. Лицензии

- FFmpeg-сборки с `libx264` распространяются под GPL. Приложение вызывает `ffmpeg.exe`
  как отдельный процесс и не линкуется с ним, поэтому код приложения GPL не обязан быть;
  в дистрибутив кладётся текст лицензии и ссылка на исходники FFmpeg (требование GPL).
- Если понадобится линковка (например, `FFmpeg.AutoGen`) — нужна LGPL-сборка без `libx264`
  (тогда кодирование только аппаратное или через `openh264`), либо публикация приложения под GPL.
- Лицензия самого StampCut — см. «Открытые вопросы».

## 10. Этапы и ориентировочные сроки

Оценки — для одного разработчика с опытом .NET, диапазон «оптимистично — реалистично».

| Этап | Содержание | Срок |
|---|---|---|
| 0. Проверка без разработки | Неделя работы редакции на Clipchamp (встроен в Windows 11) и на CLI-скрипте `scripts/stampcut.ps1`. Цель — подтвердить, что нужен именно свой инструмент, и собрать реальные исходники с телефонов для тестов | 1 неделя (без разработчика) |
| 1. MVP | Всё с приоритетом **M**: открытие, прокси, превью, обрезка, склейка, оверлеи, кроп, ретушь, запикивание, пресеты, GPU, экспорт, lossless, установщик | 4–6 недель |
| 2. Редакционный режим | Приоритет **S**: пакетная обработка, до 3 оверлеев, общая библиотека, аппаратное кодирование, миниатюры, loudnorm | 2–3 недели |
| 3. По запросу | Приоритет **C** | по отдельному решению |

Каждый этап заканчивается сборкой установщика и прогоном на эталонном наборе исходников.

## 11. Критерии приёмки MVP

1. На эталонном наборе (не меньше 10 роликов: iPhone HEVC HDR 4K60, iPhone H.264,
   Samsung, Xiaomi, Pixel, пересланный через Telegram/WhatsApp, горизонтальный и
   вертикальный, с поворотом в метаданных, с переменной частотой кадров) все файлы
   открываются, показывают первый кадр и экспортируются без ошибок.
2. Экспортированные файлы: H.264 High ≤ 4.1, `yuv420p`, ≤ 1920 по длинной стороне,
   ≤ 30 к/с, постоянная частота кадров, AAC 48 кГц, `moov` в начале — проверяется `ffprobe`.
3. Telegram Desktop и Telegram на iOS/Android проигрывают файл встроенным плеером без
   «чёрного квадрата», с правильной ориентацией; загрузка в VK и YouTube проходит.
4. Оверлей на экспортированном видео совпадает с превью по положению и размеру с
   точностью до 1 % размера кадра; прозрачность визуально соответствует.
5. HDR-исходник после экспорта не выглядит блёклым или пересвеченным по сравнению с тем,
   как его показывает телефон (оценка редактором на 3 файлах).
6. Lossless-обрезка 2 ГБ файла — до 5 с, качество побитово совпадает с исходным потоком.
7. Сценарий А выполняется новым сотрудником без инструкции за 2 минуты, с инструкцией
   на один экран — за 1 минуту.
8. Показатели NFR-1…NFR-4 подтверждены замерами на целевом ноутбуке.
9. Отмена экспорта не оставляет временных файлов; журналы пишутся.

## 12. Риски

| Риск | Влияние | Снижение |
|---|---|---|
| Тонмэппинг HDR на CPU медленный (в тесте: 4K60 HDR → 1080p30 примерно в 6 раз дольше реального времени) | Долгий экспорт роликов с iPhone | Прокси и экспорт через `libplacebo` на GPU, если доступен; предупреждение «HDR, экспорт займёт N минут»; возможность отключить тонмэппинг в пресете |
| HEVC-исходники не играют в `MediaElement` без расширения из Store | Нет превью | Прокси (FR-1.4) — базовое решение, не зависящее от Store |
| Аппаратные кодеры ведут себя по-разному на разных драйверах | Ошибки экспорта у части сотрудников | Тестовый прогон при первом запуске, откат на `libx264`, настройка «всегда программно» |
| Telegram пережимает видео при отправке «как видео» | Качество падает независимо от нас | Инструкция: для максимального качества отправлять «как файл»; пресет держит битрейт умеренным, чтобы пережатие было незаметным |
| Разные телефоны пишут поворот по-разному (матрица в `tkhd` vs side-data) | Экспорт «лёжа» | Опора на автоповорот ffmpeg; эталонный набор с повёрнутыми файлами в тестах |
| Экспорт в сетевую папку/OneDrive медленный или рвётся | Ошибки | Запись во временный файл рядом с исходником, затем перенос |
